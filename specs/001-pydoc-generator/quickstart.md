# Quickstart: Python Documentation Generator

**Branch**: `001-pydoc-generator` | **Date**: 2026-09-08 | **Plan**: [plan.md](plan.md)

This is a runnable validation guide for the feature. It proves the tool works
end-to-end (parse → extract → generate HTML). Implementation details live in
`tasks.md` and the implementation phase.

## Prerequisites

- Rust stable toolchain (`rustc`, `cargo`) installed via
  [rustup](https://rustup.rs/).
- A sample Python package to document (see sample fixtures below).

## Setup

```bash
# From the repository root
cargo build
```

## Building the documentation for a sample package

Given a sample package such as:

```text
samplepkg/
└── utils.py
```

Run the generator:

```bash
cargo run -- <input_dir> <output_dir>
# e.g.
cargo run -- samplepkg ./docs-output
```

Expected outcome: an HTML site is written to `./docs-output` containing an
entry for every module, class, and function in `samplepkg`, each identified
by its full Python package import path, with a navigation index.

## Validation scenarios

### 1. Documented elements (SC-002, FR-004)

- Give `utils.py` JavaDoc-style docstrings using `@arg`, `@return`, and
  `@raises` on a module, a class, and a function.
- Run the generator.
- **Expected**: The HTML site contains entries for each documented element with
  their description, argument list, return value, and raised exceptions
  (element content on each module's page, reachable from the index).
- **Acceptance scenario from spec**: `Given a codebase with JavaDoc-style
  docstrings ..., When the generator runs, Then the HTML output contains a
  page/section for each documented element with its full description.`

### 2. Undocumented elements (FR-008)

- Leave one function with no docstring.
- Run the generator.
- **Expected**: The function still appears in the HTML, with an
  existence-only entry (name and path, no extra description).

### 3. Malformed docstrings (FR-007, SC-005)

- Give one element a malformed docstring (e.g. an `@arg` without a name).
- Ensure another element is documented correctly.
- Run the generator.
- **Expected**: The run completes (does not fail). The malformed element's
  entry shows an error message stating the docstring was not written
  correctly; the correctly documented element still has full documentation.

### 4. Duplicate simple names resolved by path (FR-004, SC-006)

- Have two classes named `Helper` in two different modules.
- Run the generator.
- **Expected**: Both appear, each identified by its distinct full Python
  package import path (e.g. `pkg.a.Helper` and `pkg.b.Helper`), individually
  reachable from the index.

### 5. Determinism (FR-006, SC-004)

- Run the generator twice on unchanged input.
- **Expected**: Byte-for-byte identical output.

## Boundary inputs

- Empty directory / directory with no Python files: completes with an empty
  or minimal site and no crash.
- Non-existent input path: useful error, no crash.
- Unrecognized tag in a docstring: the unrecognized line is handled without
  failing the run (see tag scope in [docstring-syntax](contracts/docstring-syntax.md)).
